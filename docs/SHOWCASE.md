# Show your setup / Zeig dein Setup

**[English](#english) · [Deutsch](#deutsch)**

## English

Sharing a real setup helps other people assess whether Horizon fits their own hardware. Share what you can substantiate; a good post is more useful than a polished claim.

### Before you record or post

1. Get permission from every person whose voice, image, name, calendar, message, address or home could appear.
2. Use a test room, synthetic data or a neutral dashboard where possible.
3. Remove or blur QR codes, setup codes, tokens, Gateway URLs, device IDs, Bluetooth addresses, Wi-Fi names, private calendar entries, messages, camera frames and room audio.
4. Check reflections and notifications as well as the visible screen. A phone or monitor in frame can reveal the same private data.
5. Describe the actual release or commit, device, Android API/ABI or Pi OS, Gateway version, relevant provider and the one behavior you tested.

### A useful, honest format

> **Setup:** [device], [OS/API and ABI or Pi OS], Jarvis Horizon [release/commit], Gateway [version].
> **Tested:** [one concrete flow, for example “connected with my own setup code and used push-to-talk”].
> **Observed:** [what happened, including limits or failures].
> **Context:** [only the integrations and permissions relevant to that result].

Say “worked in my setup” rather than “works on all devices.” If a feature relies on your Gateway, provider, Home Assistant, camera, Bluetooth target or network, name that dependency without exposing its private details.

`hero.png` is the repository's concept art. The motion preview and every `showcase-*` screen below are actual renderer output using synthetic data. None of them is a recording of a home, device or live integration.

- [Motion preview GIF](assets/horizon-motion.gif) and [MP4](assets/horizon-motion.mp4)
- [Desktop UI capture](assets/horizon-demo-desktop.png) and [portrait UI capture](assets/horizon-demo-portrait.png)

Use the repository and release links beside an asset so viewers can check its source. The [public browser demo](https://the-geek-freaks.github.io/jarvis-horizon/) is the primary way to explore the interface without a device.

### Turn a result into useful project feedback

Open the **Supported device report** issue form when you can share reproducible compatibility evidence. Use the bug template for a reproducible fault and the existing feature-request template for a concrete improvement. Attach only scrubbed logs or synthetic examples.

## Deutsch

Ein echtes Setup hilft anderen einzuschätzen, ob Horizon zu ihrer Hardware passt. Teile nur, was du belegen kannst; ein guter Bericht ist nützlicher als eine polierte Behauptung.

### Vor Aufnahme oder Veröffentlichung

1. Hole die Zustimmung aller Personen ein, deren Stimme, Bild, Name, Kalender, Nachricht, Adresse oder Zuhause sichtbar oder hörbar sein könnte.
2. Nutze nach Möglichkeit einen Testraum, synthetische Daten oder ein neutrales Dashboard.
3. Entferne oder verpixele QR-Codes, Setup-Codes, Tokens, Gateway-URLs, Geräte-IDs, Bluetooth-Adressen, WLAN-Namen, private Kalendereinträge, Nachrichten, Kamerabilder und Raum-Audio.
4. Prüfe Spiegelungen und Benachrichtigungen ebenso wie den sichtbaren Bildschirm. Ein Handy oder Monitor im Bild kann dieselben privaten Daten verraten.
5. Nenne die tatsächliche Release-Version oder den Commit, Gerät, Android-API/ABI oder Pi-OS, Gateway-Version, relevanten Provider und den einen getesteten Ablauf.

### Ein nützliches, ehrliches Format

> **Setup:** [Gerät], [OS/API und ABI oder Pi-OS], Jarvis Horizon [Release/Commit], Gateway [Version].
> **Getestet:** [ein konkreter Ablauf, etwa „mit meinem eigenen Setup-Code verbunden und Push-to-Talk genutzt“].
> **Beobachtet:** [was passiert ist, einschließlich Grenzen oder Fehlern].
> **Kontext:** [nur die Integrationen und Berechtigungen, die für dieses Ergebnis relevant sind].

Schreibe „funktionierte in meinem Setup“ statt „funktioniert auf allen Geräten“. Wenn ein Feature von deinem Gateway, Provider, Home Assistant, einer Kamera, einem Bluetooth-Ziel oder Netzwerk abhängt, nenne diese Abhängigkeit, ohne private Details preiszugeben.

### Aus einem Ergebnis hilfreiches Projekt-Feedback machen

Öffne das Issue-Formular **Supported device report**, wenn du reproduzierbare Kompatibilitätsdaten teilen kannst. Für einen reproduzierbaren Fehler nutze die Bug-Vorlage, für eine konkrete Verbesserung die vorhandene Feature-Request-Vorlage. Hänge nur bereinigte Logs oder synthetische Beispiele an.
