# Product
<!-- impeccable:product-schema 1 -->

## Platform
web

## Users
People running their own OpenClaw assistant who want to reuse an Android display or Raspberry Pi as a hands-free home interface. Contributors need an honest, reproducible source build and documented contracts.

## Product Purpose
Make Jarvis Horizon discoverable, understandable and installable without distributing any private household, account or device state.

## Positioning
An independent community interface for an existing backend. The project is not a stock Echo firmware installer or an Alexa replacement with automatic feature parity. Hermes requires an adapter not currently shipped.

## Operating Context
GitHub README and documentation, viewed on desktop and mobile in light and dark themes. Android and Pi installation paths differ. The primary language is English; the user explicitly requested complete German documentation as well.

## Capabilities and Constraints
Publish only audited source and validated release artifacts. Distinguish existing private-device evidence from a clean public install. Preserve upstream licenses and reproducible native dependencies. Keep known device and backend limitations visible.

## Brand Commitments
Inherit the user's established Horizon visual identity: deep navy, restrained cyan and warm gold, a detailed orbital sphere, atmospheric depth and clear typography. Use the original concept hero in docs/assets/hero.png and label it as artwork, not an app screenshot. No personal screens, recordings, camera images, fabricated metrics or testimonials.

## Evidence on Hand
Actual Android device deployments on Archos Hello 7 and modified Echo Show 5; an existing Raspberry Pi deployment. Public install/release validation is tracked separately. The code is derived from a pinned OpenClaw source commit. Current workspace artifact manifests supply exact dependency provenance.

## Product Principles
1. Lead with the useful experience and a clear install path.
2. Explain prerequisites where they matter.
3. Make claims from source and actual validation.
4. Retain full design fidelity while optimizing measured bottlenecks.
5. Treat private installation data as outside the public distribution.

## Accessibility & Inclusion
Use meaningful image alt text, ordinary selectable Markdown text, descriptive links and legible content in both GitHub themes. Avoid decorative Unicode icons. Keep the hero static, responsive and concept-labelled. English documentation has complete German counterparts for onboarding.
